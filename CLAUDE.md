# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Foundry VTT v12 module** (`id: clustersomnia`) for the *Shadow of the Demon Lord* (`demonlord`) system. Two concerns in one module:

1. **Compendium packs** (`packs/`) — LevelDB stores for Spells, Paths, Ancestries, Party (Actors), Items, Languages and Professions, Features and Talents. Declared in `module.json`.
2. **SotDL Tracker** (`scripts/`, `templates/`, `styles/`) — a per-actor HP / custom-counter / active-effect panel opened from the Token HUD.

There is no build step, no package manager, no tests, no bundler. `scripts/*.js` are plain ES modules loaded directly by Foundry (`esmodules` in `module.json`), and paths inside the code are absolute Foundry-relative URLs (`modules/clustersomnia/templates/tracker.hbs`) — the folder must be installed/symlinked as `Data/modules/clustersomnia`.

## Development loop

Edit files → in Foundry, reload the world (F5) to pick up JS/HBS/CSS changes. Bumping `version` in `module.json` matters only for distribution, not local iteration. Verify changes in a running world; there is nothing to lint or compile.

## Architecture

- `scripts/module.js` — the only entry point. Registers the `renderTokenHUD` hook that injects the tracker button, plus a one-time `ready` migration.
- `scripts/tracker-app.js` — `TrackerApp`, the main panel.
- `scripts/effects-config-app.js` — `EffectsConfigApp`, the checkbox list choosing which of the actor's applicable effects the tracker shows.
- `scripts/persistence.js` — the two non-obvious helpers both apps depend on; read this first.

Both apps are **ApplicationV2 + HandlebarsApplicationMixin** (`foundry.applications.api`), not the legacy `Application`/`FormApplication`. Consequences to respect when editing:

- Click handlers are declared in `static DEFAULT_OPTIONS.actions` and implemented as `static #private` methods, invoked with `this` bound to the app instance and signature `(event, target)`. Templates wire them with `data-action="<name>"`.
- Templates are declared in `static PARTS`; context comes from `async _prepareContext()`.
- Anything not expressible as an action (the counter name/max text inputs) is wired manually in `_onRender` via `this.element.querySelectorAll(...)`.

`TrackerApp` keeps itself live by registering Foundry hooks (`updateActor`, `create/update/deleteActiveEffect`, `create/deleteItem`) in `_onRender` and storing their ids on `this._hooks`; `_onClose` unregisters them. The `??=` guard means they are registered once per app instance, not per re-render — **any new hook must be added to that array and will be cleaned up automatically; registering outside it leaks a listener per window.**

## Union meter (per-PG "punti unione")

`scripts/union-meter.js` draws a fixed on-screen stack of JRPG gauges, one per PC (character actors carrying the talent below, GM-owned ones like Lady Diane included), as plain DOM `#clustersomnia-union` (not an Application). Beside each bar sit the portraits of PCs *ready* for a union move with it: both PGs have >= the pair's cost and the pair isn't in `used` yet. Clicking a portrait spends the cost from both and marks the pair used (A+B == B+A, key = sorted ids joined by `|`).

A PG's points are the uses of its **"Punti Unione" talent** item (`system.uses.value`, max = `system.uses.max`, fallback 5), so the sheet and the meter always agree; PCs without that talent don't get a bar. The pairs already used this fight are the only module-owned state: world setting `unionState` `{used:[pairKey]}`, plus `unionCosts` (per-pair overrides of `unionDefaultCost`, edited in `UnionConfigApp`). Only the active GM writes: Trusted+ clients emit `{type:"union-op"}` on the module socket (ops: `delta`, `use`; `resetUsed` is GM-only) and the GM applies them serially in `applyOperation`, updating the talent items directly. Item create/update/delete hooks on that talent redraw the meter. `used` is cleared on `deleteCombat`.

Each ready-partner bubble shows `bubbleImage(actor)`: the world setting `unionImages[actorId]` if set (picked in `UnionConfigApp`), else the face crop in `art/bubbles/<name>.jpg` (file names that differ, like `alsa-bubble.jpg`, go in `BUBBLE_FILES`) (matched on any word of the actor's name, listed in `DEFAULT_BUBBLES`), else the sheet portrait. Per client, the stack is dragged by its top grip (`unionPosition`) and resized by its corner handle (`unionScale`); `placeWithin` keeps it inside the window. The settings were called `unity*` before the rename to "union": `migrateSettings` copies the old values over once on `ready` and deletes them, so keep it until no world still holds `unity*` keys.

The same rows double as the **party panel**: below the optional name each row shows stat chips (defense, speed, insanity, corruption) beside the name, healing rate right of the HP bar, the specialization after the emblem (`updateSpecialization`, `specializationOf` in `tags.js`: the highest of Str/Agi/Int/Will by current value, icon + short name, one only: a tie goes to the first in `SPECIALIZATIONS`, nothing when all four tie), then the spell castings left an optional per-PG emblem from the actor flag `clustersomnia.signature` `{image | icon, name}` (`updateSignature`; HP-row icons are FontAwesome glyphs (specializations: dumbbell, leaf, hat-wizard, hands-praying); `image` gives a picture via `miniIcon`, e.g. Zoe's umbrella; name on hover), then the spell castings left (`updateCastings`: sum of `castings.max - castings.value` over the PG's spells, since the system counts castings *used*; hidden with no spells; spell item hooks redraw it), a CSS-drawn HP bar, the union bar, and an extras line with the Tracker's displayed effects (`displayedEffects` in `persistence.js`, shared with `TrackerApp`) and counters. `system.characteristics.health.value` is the **damage taken**, not current HP (the system marks "injured" when `value >= max / 2`), so the bar shows `max - value`. Its colour blends continuously with the percentage (`hpColor`: skin `hp.down` at 0, `injured` at 50%, `ok` at 100%), like Foundry's token bars; the `injured`/`down` classes only drive the portrait ring. HP writes go through `writeDamage` (one actor at a time, a burst of clicks merged into one write of the final value, each write waiting until the system's own effect changes settle; while an actor has a write pending or in flight `updateHp` does not repaint its rows, so an older answer from the server never puts a stale value back, and the click paints every card of that PG at once via `rowsOf`): the system reacts to every health change with an async `handleHealthChange` that adds/removes the Injured/Incapacitated effects by find-then-add/delete, and two overlapping runs left duplicate effects and "ActiveEffect ... does not exist" errors. HP edits skip the socket: the hover buttons (or, in `portraitControls` skins, left/right click on the bar itself: heal/hurt, Shift ±5, mirroring the portrait's union points) call `actor.update` and appear only when `actor.canUserModify(game.user, "update")`; the row key in `renderMeter` includes that permission so rows rebuild when it changes. Per-client settings `unionShowStats` / `unionShowEffects` / `unionShowCounters` toggle the details (`DETAIL_SETTINGS`). Actor, ActiveEffect and spell hooks name the actor they touch and only that row is redrawn (`redrawSoon(actorId)`, `renderMeter(only)`); the union talent and settings redraw everything, because the union points decide who is ready with whom. The HP colour comes from the three skin colours parsed once per host in `applySkinVars` (`el._hpColors`): never `getComputedStyle` in the per-row update path, it forces a layout per row.

**Cards are reusable.** `cardsMarkup` / `wireCards` / `updateRows` in `union-meter.js` build, wire and fill the `.cu-row` cards for any element; `mountPartyCards(host, scaleSetting)` registers a host that is refreshed together with the floating stack (`refreshHosts` runs at the top of `renderMeter`, and dead hosts are dropped). The stack itself is just one host plus its grip/resize. `scripts/combat-party.js` mounts one in the Combat Tracker (inside a `.clustersomnia-party-wrap` section with a "Party" fold bar, client setting `unionCombatCollapsed`; folded, CSS hides the cards). The section is built once and the same element is put back after every `renderCombatTracker`, because the tracker replaces its content on each render and rebuilding the cards made them flash. For the same reason every card update goes through `syncChildren` in `union-meter.js`, which replaces a container's children only when what they would draw has changed: never `replaceChildren` directly, or each redraw of the party recreates every bubble, tag and icon (pictures reload, animations restart) (`renderCombatTracker`, recreated on every render) with its own scale setting `unionCombatScale` and toggle `unionShowInCombat`. Card CSS is scoped to `.cu-host`, never to `#clustersomnia-union`; only grip, resize and the stack's pointer rules stay on the id. To show the cards somewhere else, create an element there and call `mountPartyCards` with a client scale setting.

**Tags.** Every card (compact, expanded and personal) carries a `.cu-tags` row of plain coloured text + stacked chevron arrows (`updateTags`; one arrow per buff/debuff *entry*, a special 10th step (`MAX_STEPS`, `levelOf(...).special`) swaps the arrows for an animated emblem, `ARROWS_PER_TIER` arrows fill a tier and the next entry restarts in the next colour: white-yellow, orange, hot red / light violet, violet, deep violet) built by `effectTags(actor)` in `scripts/tags.js`: automatic ones from **every active effect** (world setting `tagsEveryEffect`, default on; when off, only effects that are *temporary* (spell / hand-made (`character`) / affliction `flags.sourceType`, or any effect with a duration; the `permanent` flag alone is not reliable, Soft Leather says false) **or picked in the Tracker's "Search Effects"** (`displayedEffects`): nothing in the data separates a removable talent (Sand Orb) from a class one (Perizia marziale), so that is the player's call) mapped by change key to categories (an effect can feed several: attack `boons` feed both Hit and Crit; the challenge boons `all` feed Str, Agi, Int, Wil and Per at once) (`TAG_CATEGORIES`: Atk Mag Hit Crit Def Str Agi Int Wil Per Spd HP Pow Size; a bare `attack.damage` key counts for Atk like `damage.all`; spell damage/boons are Mag, not Atk/Hit/Crit; a size effect is applied to the base size in its own mode (multiply/add/override) and is up or down by the result), direction from the sign of the value (never the size: one effect is one step per category); plus manual ones, the object flag `clustersomnia.tags` `{atk: 2, def: -1}` (signed number of steps, added to the automatic ones; the old "up"/"up2" strings are still read) on the world actor, cycled from the Tracker's Tag section (`-=id` deletes a key). No values are shown.

**Expanding.** A left click on any portrait toggles that card's expanded state (`toggleExpanded`, client setting `unionExpanded` `{ids}`, part of `cardsKey` so the card rebuilds); an expanded card adds the effects/counters line like the personal card does. Hosts mounted with `extras: true` are always expanded and have no portrait toggle (`wireCards(root, skin, extras)`). The old portrait click for union points moved to the union bar (tiles + icon).

**Shared cards are compact; the personal card has everything.** The floating stack and the Combat Tracker host show portrait, name, DEF/SPD, HP + HR and the union bar, never effects or counters unless expanded. Those live on the *personal card* (`scripts/personal-card.js`, `#clustersomnia-mine`): one floating card per client, mounted with `mountPartyCards(host, "unionMineScale", { extras: true, pick, floating, onFilled })`. `extras` adds the effects/counters line (toggled by `unionShowEffects` / `unionShowCounters`), `pick(party)` chooses whose card it shows (the user's `character`; for the GM the last selected party token), and `floating` adds the drag grip and resize handle, saving to its own `unionMinePosition` / `unionMineScale` settings. `enableDrag` / `enableResize` take the setting names, and floating hosts carry the class `cu-floating` (the stack too); the CSS for grip, resize and pointer rules hangs on that class, not on an id. `refreshPartyCards()` redraws everything, for hooks like `controlToken`.

**Scene-controls button.** `scripts/party-toggle.js` appends two `li.scene-control` buttons to `#controls ol.main-controls` on every `renderSceneControls` (added after Foundry binds its click handlers, so Foundry never sees them): the multiple tracker (client setting `unionShow`) and the personal card (`unionShowMine`); `clientSettingChanged` keeps their highlight in sync. Add a button by adding an entry to `TOGGLES`.

**Detaching.** The stack and the personal card have a `.cu-popout` button in `CARD_CHROME`; `popOut(el, key, onDock)` in `scripts/popout.js` opens a `window.open` popup, copies the head's stylesheets, and *moves the same element* into it (`cu-detached` class), so hooks, handlers and `fillHost` keep working untouched. The window fits the card with `zoom` on its body (ResizeObserver + `resize`), and `pagehide` puts the element back on the main document and saves `{x, y, w, h}` in the client setting `unionPopouts[key]` so it reopens in the same place (second screen). Anything that removes a floating card must call `closePopout(el)` first. The same mechanism detaches Foundry's own (ApplicationV1) actor sheets: `scripts/sheet-popout.js` adds a header button through `getActorSheetHeaderButtons`, `popOutApp(app)` moves `app.element` into the popup (class `cu-app-detached` fills the window), and the `close<SheetClass>` hook closes the popup when the sheet closes. Menus, dialogs and item sheets opened from a detached sheet still open in the main window. Because the element lives in another document, `document.getElementById` no longer finds it while detached (use the window from `window.open("", "clustersomnia-<key>")`), and Foundry's `data-tooltip` doesn't show there (`title` does).

Name and stat chips share one `.cu-head` line (the name falls back to `shortName(actor)` there so stats don't truncate it). A `segments.gradient` list of colours gives each union tile its own colour along the scale (`segmentColor`, set as `--seg-c` / `--seg-hi` per tile; Daniele v1 uses colours taken from the PU icon). Skins can also set `font`, `hp` colours and `readyColor`, exposed as CSS variables (`--cu-font`, `--cu-hp-*`, `--cu-ready`) in `buildRows`. The world's saved `unionSkin` wins over `DEFAULT_SKIN`, so a new preset only shows after picking it in the settings.

Skins live in `skins/<name>/` (`skin.json` + frame/fill images) or in any user folder set in `unionSkinFolder`. The fill image is revealed with a slanted `clip-path` driven by `track.x0/x1/slant` (percent of the artwork); the keys are documented for artists in `skins/README.md`. Optional behaviour keys: `showName: false` hides the PG name, `showText: false` drops the value label, `portraitControls: true` replaces the hover −/+ buttons with left click (+1) / right click (−1) on the union bar (tiles and its icon, not the ready partners) and, for HP, on the HP bar (left heals, right hurts), `bubbleAnimation: false` stills the ready bubbles (no preset uses it now), `portraitSize` / `portraitShift` size and nudge the portrait. Preset choices are hardcoded in `PRESET_SKINS`.

## Weapon damage by size

`scripts/weapon-size-damage.js` lets a weapon carry a table of damage by creature size. It is edited in a "Damage by size" row that the `renderDLBaseItemSheet` hook adds under "Damage" on the system's V2 weapon sheet (rows are wrapped in `.item-group-damage` because the sheet styles its rows through the group class), and it is stored in the item flag `clustersomnia.damageBySize` = `[{ size: "1/4", damage: "1" }, ...]`. When the weapon is used, `damageForSize(item, size)` picks the row for the attacker's *current* derived size (`actor.system.characteristics.size`, so a size effect like Forma Gatto counts): an exact match, else the largest listed size below it, else nothing (the base `system.action.damage` stays). The pick is applied by a wrapper around `DemonlordActor#rollItemAttack`, installed on `ready`: it swaps `item.system.action.damage` in memory for the duration of the attack (the chat card is built from it, synchronously inside `postAttackToChat`) and restores it in `finally`, so nothing is saved on the item. Besides the table, a weapon can follow the game's size rule: the "Follow the size rule" switch on the same row group sets the item flag `clustersomnia.sizeRule`, and `ruleDamage(base, size)` then gives +1d6 per point of Size above 1 (flat bonuses stay; a plain-d6 damage merges, 2d6+1 at Size 3 becomes 4d6+1). A weapon "below 1d6" is decided simply: a single die from d2 to d5, or no dice at all; it first becomes 1d6 at Size 2, i.e. (Size - 1)d6 plus its flat bonus. Size 1 or smaller changes nothing. The table is checked first and wins; the rule only applies when no table row is at or below the size. The sheet hides native checkboxes, so the switch is a drawn `role=switch` row. Weapons only; the actor sheet's weapon list still shows the base damage. Foundry v12 has no `foundry.utils.escapeHTML` (use `Handlebars.Utils.escapeExpression`).

## System health handler guard

`scripts/health-guard.js` wraps `DemonlordActor#handleHealthChange` (installed on `ready`). The system calls it on every health change to add/remove the Injured/Incapacitated effects with `findAddEffect` / `findDeleteEffect`, which check first and act after an await, and it updates the actor again itself (the `injured` flag), re-entering before it finished. Overlapping runs created duplicate effects (two Injured on one PG) and "ActiveEffect ... does not exist" errors. The wrapper runs it one at a time per actor and merges calls that arrive meanwhile into one extra pass (it returns at once to those callers: waiting would deadlock with its own nested update). If a system update renames the method the module logs a warning and the guard is off.

## Persistence rules (easy to get wrong)

- Flag namespace is `"clustersomnia"`, hardcoded as `FLAG_NAMESPACE` in each script. `"my-tracker"` is the **legacy** namespace from a now-deleted standalone module; `module.js` migrates leftover `counters` / `displayedEffectIds` off it once, GM-only, on `ready`. Do not write to the legacy namespace.
- `persistenceActor(actor)` from `persistence.js` resolves an unlinked token's synthetic actor to its world `baseActor`. Effect-selection flags **must** go through it, otherwise they are written into scene token data and vanish with the token. (Counters go through it too: the Tracker opened from an unlinked token used to save them on the token, invisible to the party cards.) A counter is `{id, name, value, max|null, icon?}`: `icon` is set from the Tracker with Foundry's `FilePicker` (right click clears it), and the party cards draw every counter as an icon plus a badge with the current value only (`updateExtras`, `.cu-counter-badge`); without an icon the box shows the name's initials (`counterInitials`). Counters and effects both live only on expanded cards (and the personal one).
- `effectKey(effect)` produces a scene-independent effect id (`Item.<id>.ActiveEffect.<id>` or `ActiveEffect.<id>`). Never persist `effect.uuid` for token actors — it embeds scene and token ids and will not match elsewhere. Reads still accept raw uuids for backwards compatibility with older saved data.

## Compendium packs

`packs/*` are binary LevelDB directories (`.ldb`, `MANIFEST-*`, `CURRENT`), marked `binary` in `.gitattributes` — never diffable, and merge conflicts there cannot be resolved by hand. **They are a build output.** The source of truth is `src/packs/`: one YAML file per document, laid out in directories mirroring the compendium's folder tree (`_Folder.yml` describes each folder). Both are committed, because Foundry loads `packs/`.

```
npm install               # once
npm run packs:extract     # packs/  -> src/packs/   (after editing in Foundry's UI)
npm run packs:compile     # src/packs/ -> packs/    (after editing the YAML by hand)
```

`tools/packs.mjs` drives both directions via `@foundryvtt/foundryvtt-cli`, iterating the pack list in `module.json` (so a new pack needs no tooling change). Either editing route is valid — Foundry's compendium UI or the YAML — but **the two must not be edited concurrently**: whichever direction you run last overwrites the other side. Round-tripping is lossless (verified: extract → compile → extract is byte-identical).

Editing the YAML:

- **Never change `_id`.** Item and folder ids back every pack UUID, actor link and effect key; changing one silently breaks references.
- **Move an item or a folder by moving its file/directory.** `compilePack` itself only reads the `folder` field and ignores file location, so `tools/packs.mjs compile` runs a reconcile pass first that rewrites each document's `folder` (and `_key`) to match the directory it sits in. It logs every document it fixes, and the change lands in `src/packs/` so it shows up in `git diff`.
- Renaming a *directory* does nothing — a folder's display name is the `name` field in its `_Folder.yml`. Rename there; the next `packs:extract` renames the directory to match.
- A new folder is a new directory containing a `_Folder.yml` with a fresh 16-char alphanumeric `_id`, `_key: "!folders!<id>"`, `name`, `type` matching the pack's document type, and `sorting`/`sort`. Order within a folder is the integer `sort`.

Pack ownership is `PLAYER: OBSERVER`, `TRUSTED: OWNER`, `ASSISTANT: OWNER`. **Trusted Player is the deliberate content-builder role** — trusted users may create, edit and delete pack contents, plain players may only read and import. Ownership is pack-wide (folders carry no `ownership` field), so a trusted user can edit any document in a pack, including canonical content. Note that a GM who configures ownership for a pack inside the world overrides this block; the world's value wins.

Operational notes:

- **Close Foundry (or at least the world) before running either script**, and reload the world after a compile. Both directions open the LevelDB store; `extract` is logically read-only but still triggers LevelDB log recovery, so it rewrites `.log`/`MANIFEST-*` files and dirties `packs/` in git even when no data changed.
- Foundry regenerates `LOCK`, `LOG`, `LOG.old` on every open; these are gitignored.
- `packs/immagini/` is loose artwork and is deliberately **not** declared in `module.json`, so the tooling skips it. Two real pack directories also contain stray images (`packs/ancestries/536px-Concept_Viera.jpg`, `packs/items/Super Gattos.jpg`) — compile writes into the existing directory rather than replacing it, so these survive. Never `rm -rf` a pack directory.
